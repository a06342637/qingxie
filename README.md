# 轻写 · 云平台填写助手（Linode / Oracle Cloud）

可直接通过 Chrome 开发者模式加载，无需上架、打包签名或安装 Node.js。项目目录就是插件目录。

## 导入 Chrome

1. 打开 Chrome，在地址栏输入 `chrome://extensions`。
2. 打开右上角的 **开发者模式**。
3. 点击 **加载已解压的扩展程序**。
4. 选择 **`C:\Users\adminuser\Downloads\chajian`**，即包含 `manifest.json` 的文件夹。
5. 在 Chrome 右上角的拼图菜单中找到 **轻写 · 云平台填写助手**，点击图钉固定。
6. 打开 `https://login.linode.com/signup` 或 `https://signup.cloud.oracle.com/`，点击工具栏上的轻写图标，会在图标下方展开工具栏弹窗。

如果使用 ZIP，先解压，再选择解压后含 `manifest.json` 的文件夹。不要直接选 ZIP。插件加载后不要移动或删除这个目录。

更新文件后，在扩展管理页点击轻写的 **重新加载**，关闭旧工具界面，再点击插件图标。浮窗会尝试自动连接已打开的 Linode 网页；若仍提示未连接，可点击右上角 **重新识别**，或刷新 Linode 网页。

**v1.7.0 工具栏弹窗版**：弹窗宽 **720**、高 **600** 像素，贴在工具栏图标下方展开，没有独立窗口标题栏。Chrome 原生工具栏弹窗高度上限约 600 像素，屏幕可用空间不足时可能进一步缩小。左侧步骤按当前平台固定展示（LINODE 五个、ORACLE 四个），账户资料与 Oracle 地址采用三列布局，以展示更多字段。更新时关闭之前打开的独立窗口，再重新加载插件；此后点击图标直接展开工具栏弹窗。原有持久资料和设置继续保留。

## 使用方式

底部导航为 AWS、LINODE、ORACLE、AZURE、设置。目前 LINODE 与 ORACLE 可填写，AWS 和 AZURE 已预留页面。

左侧步骤栏不滚动，底部导航和填写按钮固定可见。右侧表单和文本框隐藏滚动条；较小屏幕、展开内容或较长设置页仍可用鼠标滚轮、触控板和键盘查看。点击弹窗外或按 Esc 会收起界面；再次点击插件图标可重新打开。普通字段、设置和当前步骤会保存；未解析的粘贴文本仅在浏览器会话内存中临时保留，不写入本机持久草稿。

弹窗连接当前浏览器窗口的活动网页；切到另一个标签页后重新点插件图标，即可连接该页面。

1. **注册账号**：填写邮箱、用户名、密码，点击 **模拟手动写入**。
2. **邮箱验证**：在网页进入邮箱验证后，选择该步骤，粘贴 6 位验证码并填写。
3. **手机验证**：填国家代码与手机号码，点击 **仅填写手机号**。在网页点击发送短信；收到短信后，粘贴验证码，再点 **仅填写验证码**。也可在验证码输入框已经开放时一次填写全部。
4. **账户资料**：填国家、姓名、地址、城市、省/州、邮编等。公司、地址补充和税号可留空。已验证且不可编辑的电话号码保持网页原样。
5. **卡片信息**：先在网页完成账户资料并点击 Continue，出现卡片区域后，填卡号、有效期、安全码。

所有步骤仅填写你提供的内容。注册、发送短信、验证、接受条款、Continue 和支付/绑定卡片按钮都由你在网页操作。验证码需要自行从邮件或短信中取得。

网页跳转后可手动选择左侧步骤，或点击面板右上方 **重新识别** 自动切换到检测到的步骤。所选步骤与网页不匹配时，填写按钮不可用。

## ORACLE 使用方式

切换到 **ORACLE** 平台后，左侧为四个步骤，全部针对 `https://signup.cloud.oracle.com/` 的 Oracle Cloud 免费试用注册流程。

1. **账户信息**：先选 **账单国家/地区**，再填名、姓、邮箱，然后在网页点击 **Verify my email**。国家是网页上的搜索型下拉框，插件会展开菜单并选中匹配项；可以填英文全名（如 `Trinidad and Tobago`）或两位代码（如 `TT`、`US`）。
2. **密码与账户**：填密码和确认密码，选择 **个人** 或 **公司**。公司账户多一个 **公司法定名称** 输入框，个人账户不需要。再填 **云账户 / 租户名** 和 **主区域（Home Region）**。确认密码留空时会自动使用密码。
3. **地址信息**：填地址1、城市、省/州、邮编和手机号。地址2、地址3、省份和区县留空即可，网页没有显示的输入框会自动跳过。手机号请带国家代码，例如 `+18681234567`。
4. **卡片信息**：先在网页点击 **Add payment verification method** 打开支付框，再选卡类型并填写卡号、有效期和安全码。支付表单在 Oracle 的支付 iframe 里，插件会自动定位。

国家不同，地址页的输入框数量不同：美国等国在邮编或手机号附近多一个 **区县（County）**，冷门国家可能出现地址3、省份等更多框。插件按网页实际显示的可填写项处理，留空的项不处理。

Oracle 的整段粘贴：账户信息页默认四行，依次为账单国家/地区、名、姓、邮箱；卡片页默认五段 `卡类型|卡号|月份|年份|cvv`，卡类型可省略写成四段。同样支持字段名和 JSON，点击 **查看本页格式** 可插入当前步骤的模板。

主区域（Home Region）注册后不可更改，请先确认再填写。Oracle 的邮箱验证码与手机验证步骤未包含在这四个步骤内，需要时在网页手动完成。

## 整段粘贴

展开 **整段粘贴**，粘贴后点击 **解析内容**，核对上方字段，再开始填写。点击 **查看本页格式** 可插入当前步骤的空模板。

注册页默认使用三行格式，依次为邮箱、用户名、密码；密码里的 `|`、`----`、冒号和首尾空格会原样保留：

```text
your-email@example.com
your_username
your_password
```

卡片页默认使用四段格式：

```text
卡号|月份|年份|cvv
```

月份支持 `9` 或 `09`，年份支持 `29` 或 `2029`，会自动组合为 `09/2029`；CVV 前导零会保留。一次只解析一张卡。

仍支持用字段名称标注，例如注册页：

```text
邮箱：your-email@example.com
用户名：your_username
密码：your_password
```

账户资料示例：

```text
国家：US
名：你的名
姓：你的姓
地址：你的街道地址
城市：你的城市
州：CA
邮编：你的邮政编码
```

支持中文/英文名称、JSON、逐行文本、Tab、`----` 或 `|` 分隔。注册三行格式和卡片四段格式优先按上述规则解析；其他无字段名称的内容按面板上字段顺序解释。账户资料请使用带名称的格式或手动填写，当前不支持直接解析 Google 地图地址。JSON 中的卡号、验证码、手机号、安全码必须使用带引号的字符串，避免前导零或长数字精度丢失。

国家支持网页中的国家英文名称、两位代码（如 US、CN、GB），以及部分常用中文名称。省/州支持完整名称或网页选项里的代码。下拉选项必须存在于网页；无法唯一匹配时会提示核对。只填电话区号 `+1` 无法唯一确定国家，请填写 US 或 CA。

国家字段不接受含数字或邮政符号的内容，避免把整段地址误填为国家。解析失败时，原有字段和粘贴文本会保留，错误提示显示在粘贴框下方；请按带字段名的格式修正后重试。

有效期支持 `09/29`、`09/2029`、`0929`、`092029`，适配所提供页面的 `MM/YYYY` 格式化逻辑。

## 设置

- **字符间隔**：20–500 毫秒，越小越快；提供舒缓、日常、快速三档。
- **间隔浮动**：0–80%，控制输入间隔的随机变化。
- **字段停顿**：0–2000 毫秒。
- **打错后删除**：独立开关，开启后概率为 **1–100%**，默认概率 8%。适用于所有文字和数字输入框，包括邮箱、用户名、密码、验证码、手机号、姓名、公司、地址、城市、邮编、税号及卡片；下拉框直接选择。每次开始输入一段内容时按概率决定是否先打错 1–3 个字符，等待后逐个退格，再输入这一段的正确内容。例如 `12366 → 1236 → 123 → 1234 → 12345`。100% 表示每段都先打错再修正，正确重写时不重复触发。填写完成时核对最终内容。
- **修正前停顿**：80–1000 毫秒，默认 240 毫秒，从一段错字打完开始计时。错字输入、逐个退格和正确重写均遵循字符间隔设置。旧设置的 0% 会迁移为关闭开关，原有非零概率会继续保留并开启。
- **已有内容**：默认跳过；也可清空重填，或追加普通文本。追加模式下，密码、验证码、手机号和卡片仍为替换。
- **记住普通资料**：可关闭；关闭后删除本地持久草稿，当前面板里仍可继续编辑。

默认的“跳过”也包括网页预选的国家。如果需要改写这些选项，请在设置中改为 **清空后重新填写**。留空的字段不会删除网页原有内容。

填写时可点击 **暂停 / 继续 / 停止**。网页里按 **Esc** 可停止，手动点击或按键会暂停。切换标签页时自动暂停，回到原网页再点击继续。停止保留已经输入的内容；如在错字修正过程中停止，请检查当前字段。

填写任务运行在网页中，浮窗关闭后仍可继续；重新打开浮窗会恢复当前任务进度。手动点击网页会触发“手动操作暂停”，回到浮窗后点击继续即可。即使浮窗关闭，步骤完成后仍会由后台清空该步骤的临时敏感资料。

## 本机存储

普通资料只保存在此 Chrome 配置的 `chrome.storage.local`，不做网络上传或账号同步。

密码、验证码和卡片资料只保留在面板内存和 `chrome.storage.session` 中，不写入持久草稿。完成该步骤后清空敏感字段；停止或出错时保留，以便核对重试。临时草稿最后保存 15 分钟后失效，浏览器重启后失效。设置里的 **清空所有资料** 可立即删除插件草稿，不清除网页里的已填内容。

此插件没有远程服务、统计脚本、验证码接收服务或调试器权限。插件的站点权限为 `https://login.linode.com/*`、`https://signup.cloud.oracle.com/*` 和 `https://shop.oracle.com/*`（最后一个是 Oracle 支付框所在域）。资料输入到网页后，会按网页自身的逻辑处理。

## 适配范围

已根据提供的页面 HTML 和公开注册页核实字段。

LINODE：

| 步骤 | 核心字段 |
| --- | --- |
| 注册 | `email`、`username`、`password` |
| 邮箱验证码 | `otp`，位于邮箱验证页面 |
| 手机验证 | `iso_code`、`phone_number`、`otp` |
| 账户资料 | `country`、`first_name`、`last_name`、`company_name`、`address_1`、`address_2`、`city`、`state`、`zip_code`、`tax_id` |
| 卡片 | `cc_number`、`cc_expiration`、`cvv` |

ORACLE：

| 步骤 | 核心字段 |
| --- | --- |
| 账户信息 | `country`（react-select）、`firstName`、`lastName`、`email` |
| 密码与账户 | `password`、`matchPassword`、`customer-type`、`organization`、`accountName`、`homeRegion`（react-select） |
| 地址信息 | `address1`、`address2`、`address3`、`city`、`state`、`province`、`postalcode`、`county`、`phoneNumber` |
| 卡片 | `cc_number`、`cc_expiration`、`cvv`（在支付 iframe 内，按通用特征识别） |

采用逐字写入 DOM、触发输入事件的方式，属于程序输入，事件不会伪装为真实物理键盘事件。网页若拒绝这类输入，需要手动填写。Oracle 的卡片字段位于支付网关的嵌套 iframe 中，目前按 `autocomplete`、`name`、`placeholder` 等通用特征识别，未逐字段核实；若支付框结构变化，可能需要手动填写。网页字段重命名或新流程同样不在适配范围内。

## 开发与验证

插件运行无需构建。`core.js` 定义平台、步骤、字段、解析、校验和存储分类（`platforms`、`stepsFor`、`stepById`）；`content.js` 负责网页识别与填写，包含 Linode 与 Oracle 两套识别逻辑，以及 react-select、单选按钮和支付 iframe 内的通用卡片填写；`panel.*` 是弹窗和设置；`panel-mode.js` 在首次布局前设置弹窗尺寸；`background.js` 负责注册工具栏弹窗、资料保存、任务状态、完成后的敏感资料清理和切换标签页暂停。

开发者可执行：

```text
npm install
npm test
npx playwright install chromium
npm run test:browser
npm run test:oracle
npm run test:popup
```

浏览器测试需要 Playwright 自带的 Chromium。如果本机没装，把 `CHROME_PATH` 环境变量指向已安装的 Chrome 可执行文件即可，例如 `CHROME_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe" npm run test:browser`；ARM Windows 同样用 `CHROME_PATH` 指向已安装的 ARM Chrome。测试会使用独立临时配置，通过测试环境的 CDP 接口加载插件，不修改日常浏览器配置。

浏览器测试使用按已核实字段建立的本地表单，网络路由替换为测试页面，并使用 Linode 页面实际引用的 Cleave 格式化库测试卡片。测试数据均为虚构样例。测试不提交真实注册、不发送验证码、不绑定或扣款。截图和报告在 `test-results/`。

`npm run test:oracle` 用同样的方式覆盖 Oracle：本地页面模拟 react-select 国家/主区域下拉、账户类型单选、地址条件字段，以及嵌套在支付 iframe 里的卡片表单，另外检查面板的四个步骤控件和从面板发起的填写。报告为 `test-results/oracle-report.json`。

弹窗测试通过 Chrome 实际打开工具栏弹窗，检查 720 × 600 布局、步骤和字段可见性、自动连接已有网页、收起后继续填写和草稿恢复，生成 `test-results/toolbar-popup.png`、`toolbar-profile.png` 和 `toolbar-popup-report.json`。

`npm run test:live` 是显式运行的真实页面测试，访问 `https://login.linode.com/signup`，通过插件填入虚构邮箱、用户名和密码，核对逐字输入、最终内容与原生字段校验。该测试不点击注册或 Continue，不提交表单；它使用一次性浏览器配置。2026-10-11 已验证通过，报告与截图为 `test-results/live-signup-report.json`、`live-signup.png` 和 `live-floating-window.png`。
